# 網頁儀器版面與解析度(駕駛台、教官站、情境編輯器)

> 規劃書第 7 章(駕駛台儀器)、第 9.1 節(教官站)、第 7.3 節(以內顯文書筆電為效能與版面基準)。第二十九輪(2026-11-22)以真實核心 +
> Chromium 逐頁量測後重排;判定寫成端對端測試,版面改動時由 CI 把關。第三十一輪(2026-11-26)重排 conning 條:先是視窗寬於 1900 px 時的單列,
> 再是 1900 px 以下的兩列(船上文書筆電與教官筆電實際看到的排法;都在第 2.5 節)。

## 1. 目標解析度

| 視窗(CSS px) | 代表的機器 | 備註 |
|---|---|---|
| 1366×768 | 船上文書筆電(最常見的低階面板) | 最嚴格:中段高度最小 |
| 1536×864 | 1920×1080 筆電在 Windows 125 % 縮放 | 教官筆電最常見 |
| 1600×900 | 1600×900 筆電 / 外接螢幕 | |
| 1920×1080 | 外接螢幕、100 % 縮放 | 瀏覽器視窗高度常不足 1080(工作列、分頁列) |
| 2560×1440 | 大螢幕 | 不可退步 |

1280×720 與 1024 寬以下只要求「不比原本差」(情境編輯器在 1150 px 以下自動改一欄)。

## 2. 各頁的排法

### 2.1 駕駛台 `index.html`(`src/Instruments.Web/src/app.ts`)

- 兩欄五列:header、conning 條跨兩欄;左欄是航跡圖(中段)與操船台(下段:操舵、車鐘、艏側推、自動舵、教官小面板),
  右欄最上方是 BNWAS,其下的**警報面板與 VHF(`.alert-col`)跨中段與下段兩列**。右欄只佔中段時,1366×768 / 1536×864 的中段只剩約 225–300 px,
  警報面板被擠到高度 0、VHF 下半被操船台蓋住(第二十九輪 L2 量測)。
- **視窗高度 ≤ 800 px 時 BNWAS 改到航跡圖下方**(橫跨左欄的一列,約 36 px;`bnwas-indicator.ts` 在格子寬 ≥ 560 px 時以 `@container` 排成一列,
  字級與「重設」鈕大小不變),右欄整欄給警報面板與 VHF。原因(第二十九輪 L3 量測):E09 失電後 header 因 5 個故障徽章折成兩行,
  右欄在 1280×720 只剩 402 px、1366×768 只剩 434 px;BNWAS(62)+ 2 筆警報(164)+ VHF(228–292)在字級與觸控目標不縮的前提下放不下,
  VHF 的文字欄 / 送出 / DISTRESS / URGENCY 被擠到視窗外。DOM 與 Tab 順序不變(航跡圖 → BNWAS → 警報 → VHF → 操船台);
  代價是航跡圖少約 40 px(1366×768 失電時約 183 px 高、1280×720 約 158 px)。
- 右欄是直向 flex:VHF 取自然高度,警報面板吃剩餘高度、最小 164 px(標題列 24 px 與 2 筆含「轉移」選單的警報,各 59 px),清單在面板內捲動;
  兩者仍放不下時整欄捲動。
- 右欄是尺寸容器(`container: side`):**欄高 ≤ 480 px**(警報 164 + VHF 原尺寸約 292 放不下;1536×864 約 460 px、header 兩行時約 430 px,
  1366×768 約 470 / 434 px,1280×720 約 438 / 402 px)時 VHF 只縮最次要的部分:
  - 訊息紀錄列固定為**兩則單行訊息的高度**(`calc(2lh + 6px)`,lh 是紀錄列的行高 1.3 × 11 px;Linux Chromium 約 35 px),列間距 5 → 4 px。
    紀錄列由舊到新排列並**貼底**:收到新訊息時捲到最新一則(`vhf-panel.ts` 的 `willUpdate` 記錄更新前是否在底部
    — `scrollTop + clientHeight ≥ scrollHeight − 4` — `updated` 在紀錄變多且原本在底部時捲到底,第一次與換 client 時也捲到底;
    紀錄列變矮時以 ResizeObserver 重新貼底)。所以**壓縮時看得到的是最新兩則**;最新一則折成兩行(長的 DSC 附文)時只看得到最新一則,
    但一定是最新的。使用者往上捲看舊訊息時不強制拉回,捲回底部後恢復貼底。第二十九輪 L3 時紀錄列固定 30 px 且不捲動,只看得到最舊的「VHF 已連線」(L4 修正)。
  - DSC 說明與「麥克風:按 PTT 時要求授權」整句移到 title(不截斷成半句)。
  - **無麥克風權限 / 沒有麥克風 API** 時 PTT 停用,鈕上直接寫「無麥克風 · 只能用文字 / DSC」(同時無法播放音訊時「無麥克風 / 無音訊 · 只能用文字 / DSC」;
    警示色、虛線框,不用停用的淡色),完整說明與錯誤在鈕的 title;壓縮時警示列不另佔一列(資訊已在鈕上),不壓縮時(教官站、簡化模式)照常顯示整句。
    L3 時這一列(約 26 px)固定顯示,1280×720 失電後把 DISTRESS / URGENCY 擠到視窗外(L4 修正)。只有「無法播放音訊」的警示照常顯示。
  - PTT 44 px、頻道鈕、文字欄、DSC 鈕與字級都不縮。
  以 CSS 變數 `--brm-vhf-log-min` / `--brm-vhf-log-max` / `--brm-vhf-gap` / `--brm-vhf-hint-display` / `--brm-vhf-mic-hint-display` 傳入 `vhf-panel.ts`。
- 航跡圖左上角的浮貼外力讀數(拖船 / 錨 / 靠泊)以航跡圖為界:最高到航跡圖下緣,放不下時在讀數內捲動。
  **只在讀數真的放不下時接收滑鼠**:`external-readout.ts` 以 ResizeObserver 觀察讀數本身與內容框,`scrollHeight > clientHeight + 1`
  時設 `[scrollable]` 屬性,`app.ts` 的 `.plot-wrap brm-external-readout[scrollable]` 才是 `pointer-events: auto`;放得下時不攔滑鼠,
  讀數範圍內的滾輪縮放與拖曳平移照常作用在航跡圖。實測(Linux Chromium,E13 兩艘拖船):1093×614 航跡圖約 98 px、讀數內容 116 px
  只看得到 70 px → 接收滑鼠(在讀數內捲動;這時讀數範圍內不能縮放 / 平移航跡圖,讀數以外的範圍照常);1280×720 航跡圖 194 px、
  讀數 116 = 116 → 不攔滑鼠;1366×768 以上同。L3 時 1093×614 約 120 px 高的讀數溢出到下方、蓋住 BNWAS 的標題與階段(L4 修正);
  L4 改成「航跡圖矮於 200 px 時接收滑鼠」,1280×720 的讀數放得下卻攔下讀數範圍(約占航跡圖 1/4)的滾輪與拖曳(L5 修正)。
- header:寬度 ≤ 1500 px 時核心位址(ws://…)不另外顯示,位址在連線狀態徽章的 title。故障 / 警報徽章**不合併、不隱藏**,header 可以折成兩行
  (右欄的高度就是依「header 兩行」設計的)。
- 寬度 ≤ 1900 px 時 conning 條折成兩列(`conning-bar.ts` 同一門檻;各方塊是尺寸容器,字級以 `min(vw, cqi)` 縮放,見該檔註解);
  寬於 1900 px 時排成單列。兩種排法都見第 2.5 節(兩列時第二列各方塊的寬度第三十一輪重新分配過,下面幾句裡的方塊寬度是當時量的)。
  風方塊 ≤ 185 px 寬時玫瑰圖縮小並移到數值上方,兩列數值用滿方塊寬度(字級下限 11 px 不變);
  並排時(1440 寬以上)一列放不下就把數值換到標籤下一行(靠右),不被方塊裁切。原本門檻 150 px:1280×720 並排時數值列只剩 105 px,
  本機字型(Inter)剛好 105 px,CI 的 Linux 執行器(拉丁字母 DejaVu Sans)要 110 px 而被裁切(第二十九輪 CI run 92;見第 5 節的字型重現)。
- 操船台五個面板是尺寸容器,窄時各自改排法(`helm-wheel`、`telegraph-control`、`thruster-lever`、`autopilot-panel`、`instructor-controls` 的 `@container`)。
  **寬度 ≤ 1500 px 時五格的左右內距 8 → 5 px**(面板的內距,不是鈕;鈕的大小與字級不變),省下約 30 px,欄比改為
  操舵 2.2 : 車鐘 1.03 : 艏側推 1.06 : 自動舵 1.355 : 教官小面板 0.6(第二十九輪 L5):舵令預設鈕 1280×720 約 32 px、1366×768 約 36 px 寬

  1 px,出現捲軸時 11 px / 4 px)。1280 寬以上一行放得下,排法不變。

### 2.2 完整教官站 `instructor.html`(`src/Instruments.Web/src/instructor-app.ts`)

- **conning 條在最上方、橫跨三欄**(`.full` 的第一列,在三欄的 `.body` 之前);其下三欄各自是直向 flex 容器:欄內面板不互相擠壓
  (不會被擠到高度 0 或疊到鄰居上),放不下時由欄(或欄內的捲動區)自己捲動。
- 左欄:**執行控制固定在最上方**(不在捲動區內;凍結 / 恢復 / 重設 / 結束練習與時間倍率任何高度都看得到)→ 捲動區(情境 → 時間表 → 畫面錄影)。
  情境面板佔捲動區高度的 70 %(300–440 px;捲動區較矮時與捲動區同高,但至少 260 px),不捲動時「載入」鈕就在可見範圍內;
  清單至少 80 px、選了情境時詳細區至少 120 px,**適用於面板 ≥ 294 px**(標題、兩行的「載入 <長 id>」鈕列與間距約 94 px,
  294 = 94 + 80 + 120 剛好放得下;再低清單就不到 80 px,例:290 px 時只剩 76 px);面板矮於 294 px 時 64 / 96 px

## 3. 改版面時的規則

1. 不縮小字級、不縮小觸控目標(按鈕 / 輸入框高度)來硬塞。例外是第 6 節列出、經第二十九輪審查接受的項目(1366×768 以上高 ≥ 44 px、寬 ≥ 32 px);
   比對時高度與寬度都要比(審查腳本 cmp2 的作法)。
2. 不用 `overflow: hidden`、`text-overflow: ellipsis` 把控制項或標籤裁掉來「通過」;內容放不下時讓所在的面板或欄**自己捲動**(`overflow-y: auto`)。
3. 關鍵控制(第 4 節清單)必須不捲動就看得到並點得到。
4. 不隱藏功能(教官小面板、警報按鈕等);窄時改排法。
5. 改完跑第 5 節的量測與端對端測試,並在 1366×768 與 1536×864 各看一張截圖。

## 4. 判定(端對端測試與開發量測共用)

1. 每個可見的 button / input / select / textarea:中心點的最上層元素(穿過 shadow DOM)必須是自己或自己的後代(與 Playwright 點擊前的攔截檢查相同);

2. 關鍵控制不必捲動就整個看得到(中心點與四邊中點都點得到);關鍵清單(警報清單、事件串流)的可見高度足夠,前幾列完整落在可見範圍內。
