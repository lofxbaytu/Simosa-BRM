# 網頁儀器版面與解析度(駕駛台、教官站、情境編輯器)

> 規劃書第 7 章(駕駛台儀器)、第 9.1 節(教官站)、第 7.3 節(以內顯文書筆電為效能與版面基準)。第二十九輪(2026-11-22)以真實核心 +
> Chromium 逐頁量測後重排;判定寫成端對端測試,版面改動時由 CI 把關。

## 1. 目標解析度

| 視窗(CSS px) | 代表的機器 | 備註 |
|---|---|---|
| 1366×768 | 船上文書筆電(最常見的低階面板) | 最嚴格:中段高度最小 |
| 1536×864 | 1920×1080 筆電在 Windows 125 % 縮放 | 教官筆電最常見 |
| 1600×900 | 1600×900 筆電 / 外接螢幕 | |
| 1920×1080 | 外接螢幕、100 % 縮放 | 瀏覽器視窗高度常不足 1080(工作列、分頁列) |
| 2560×1440 | 大螢幕 | 不可退步 |

1280×720 與 1024 寬以下只要求「不比原本差」(情境編輯器在 1150 px 以下自動改一欄)。

## 2. 各頁的排法

### 2.1 駕駛台 `index.html`(`src/Instruments.Web/src/app.ts`)

- 兩欄五列:header、conning 條跨兩欄;左欄是航跡圖(中段)與操船台(下段:操舵、車鐘、艏側推、自動舵、教官小面板),
  右欄最上方是 BNWAS,其下的**警報面板與 VHF(`.alert-col`)跨中段與下段兩列**。右欄只佔中段時,1366×768 / 1536×864 的中段只剩約 225–300 px,
  警報面板被擠到高度 0、VHF 下半被操船台蓋住(第二十九輪 L2 量測)。
- **視窗高度 ≤ 800 px 時 BNWAS 改到航跡圖下方**(橫跨左欄的一列,約 36 px;`bnwas-indicator.ts` 在格子寬 ≥ 560 px 時以 `@container` 排成一列,
  字級與「重設」鈕大小不變),右欄整欄給警報面板與 VHF。原因(第二十九輪 L3 量測):E09 失電後 header 因 5 個故障徽章折成兩行,
  右欄在 1280×720 只剩 402 px、1366×768 只剩 434 px;BNWAS(62)+ 2 筆警報(164)+ VHF(228–292)在字級與觸控目標不縮的前提下放不下,
  VHF 的文字欄 / 送出 / DISTRESS / URGENCY 被擠到視窗外。DOM 與 Tab 順序不變(航跡圖 → BNWAS → 警報 → VHF → 操船台);
  代價是航跡圖少約 40 px(1366×768 失電時約 183 px 高、1280×720 約 158 px)。
- 右欄是直向 flex:VHF 取自然高度,警報面板吃剩餘高度、最小 164 px(標題列 24 px 與 2 筆含「轉移」選單的警報,各 59 px),清單在面板內捲動;
  兩者仍放不下時整欄捲動。
- 右欄是尺寸容器(`container: side`):**欄高 ≤ 480 px**(警報 164 + VHF 原尺寸約 292 放不下;1536×864 約 460 px、header 兩行時約 430 px,
  1366×768 約 470 / 434 px,1280×720 約 438 / 402 px)時 VHF 只縮最次要的部分:
  - 訊息紀錄列固定為**兩則單行訊息的高度**(`calc(2lh + 6px)`,lh 是紀錄列的行高 1.3 × 11 px;Linux Chromium 約 35 px),列間距 5 → 4 px。
    紀錄列由舊到新排列並**貼底**:收到新訊息時捲到最新一則(`vhf-panel.ts` 的 `willUpdate` 記錄更新前是否在底部
    — `scrollTop + clientHeight ≥ scrollHeight − 4` — `updated` 在紀錄變多且原本在底部時捲到底,第一次與換 client 時也捲到底;
    紀錄列變矮時以 ResizeObserver 重新貼底)。所以**壓縮時看得到的是最新兩則**;最新一則折成兩行(長的 DSC 附文)時只看得到最新一則,
    但一定是最新的。使用者往上捲看舊訊息時不強制拉回,捲回底部後恢復貼底。第二十九輪 L3 時紀錄列固定 30 px 且不捲動,只看得到最舊的「VHF 已連線」(L4 修正)。
  - DSC 說明與「麥克風:按 PTT 時要求授權」整句移到 title(不截斷成半句)。
  - **無麥克風權限 / 沒有麥克風 API** 時 PTT 停用,鈕上直接寫「無麥克風 · 只能用文字 / DSC」(同時無法播放音訊時「無麥克風 / 無音訊 · 只能用文字 / DSC」;
    警示色、虛線框,不用停用的淡色),完整說明與錯誤在鈕的 title;壓縮時警示列不另佔一列(資訊已在鈕上),不壓縮時(教官站、簡化模式)照常顯示整句。

  - PTT 44 px、頻道鈕、文字欄、DSC 鈕與字級都不縮。
  以 CSS 變數 `--brm-vhf-log-min` / `--brm-vhf-log-max` / `--brm-vhf-gap` / `--brm-vhf-hint-display` / `--brm-vhf-mic-hint-display` 傳入 `vhf-panel.ts`。

  矮於 200 px 時讀數才接收滑鼠(讓使用者捲得動),平時不攔滑鼠(拖曳 / 滾輪照常作用在航跡圖)。L3 時 1093×614 的航跡圖只剩約 100 px,
  約 120 px 高的讀數溢出到下方、蓋住 BNWAS 的標題與階段(L4 修正)。
- header:寬度 ≤ 1500 px 時核心位址(ws://…)不另外顯示,位址在連線狀態徽章的 title。故障 / 警報徽章**不合併、不隱藏**,header 可以折成兩行
  (右欄的高度就是依「header 兩行」設計的)。
- 寬度 ≤ 1900 px 時 conning 條折成兩列(`conning-bar.ts` 同一門檻;各方塊是尺寸容器,字級以 `min(vw, cqi)` 縮放,見該檔註解)。
  風方塊 ≤ 150 px 寬(1093 寬的視窗)時玫瑰圖移到數值上方,兩列數值用滿方塊寬度(字級下限 11 px 不變)。

  < 180 px(1093 寬)時 ±10 移到第二列、面板比格子高時在面板內捲動。

### 2.2 完整教官站 `instructor.html`(`src/Instruments.Web/src/instructor-app.ts`)

- **conning 條在最上方、橫跨三欄**(`.full` 的第一列,在三欄的 `.body` 之前);其下三欄各自是直向 flex 容器:欄內面板不互相擠壓
  (不會被擠到高度 0 或疊到鄰居上),放不下時由欄(或欄內的捲動區)自己捲動。

  情境面板佔捲動區高度的 70 %(300–440 px;捲動區較矮時與捲動區同高,但至少 260 px),不捲動時「載入」鈕就在可見範圍內;

- 中欄:航跡圖(至少 180 px)→ 下方面板區(參與者、拖船、錨、繫纜…;最多 36vh(寬度 ≤ 1440 px 時 42vh),自己捲動;寬度 ≤ 1900 px 時改兩欄,

### 2.3 簡化教官模式、重播檢視、ECDIS、雷達、講評報告

更正(第二十九輪 L3):L2 時本節寫「各目標解析度下沒有被蓋住的控制項」,當時只量了**空白的初始畫面**。以同一份判定量
**載入紀錄後的重播檢視**與**「開始練習」後的簡化模式**,1366×768 都不通過(5d811a1 就有):重播檢視的事件串流只剩 38 px、六個篩選鈕被下一個面板蓋住
(真實點擊被攔截),講評摘要的表格被長指標名稱撐到約 1140 px 寬;簡化模式執行階段的 VHF 落在固定格列中給學員操作紀錄的那一列(約 88 px),
頻道 69–77、守聽選單、PTT、音量被 `overflow: hidden` 裁掉。L3 的修正:

- 簡化模式選擇頁:情境面板帶 `simple` 屬性,詳細區優先取自然高度(講評引導問題的標題不被推到可見範圍外),清單吃剩餘高度、至少 96 px。
- 簡化模式簡報頁:簡報文字容器用 `white-space: pre-wrap`,內含的 `<brm-briefing-block>` 與角色 / 附件列要還原 `white-space: normal`
  (否則樣板的換行被畫成空白行,1366×768 上同儕評估提示被擠到捲動範圍外)。
- 簡化模式執行階段:側欄改直向 flex,各面板取自然高度、學員操作紀錄吃剩餘高度(至少 90 px),放不下時側欄捲動;
  順序 BRM 標記 → **VHF**(PTT 不必捲動就點得到)→ 拖船 / 操舵 / 錄影 → 警報監看 → 時間表 → 學員操作。VHF 的 `.tile` 改為 `overflow-y: auto`
  (外層給的高度比內容矮時在面板內捲動,不裁掉控制項)。有語音 / 訊息橫幅時多一列給橫幅(原本橫幅被排進航跡圖那一列、壓到約 10 px)。
- 重播檢視(載入紀錄後):右欄四個面板依比例分高度且各有下限 — 事件串流 ≥ 140 px(清單 ≥ 64 px)、輸入事件 ≥ 64、BRM 標記 ≥ 56、
  講評摘要 ≥ 110 px 並在自己的面板內**直向**捲動(`brm-debrief-summary` 是捲動區;原本 `max-height: 40vh` 先取走高度);欄寬固定(`minmax(0, 1fr)`);
  連下限都放不下時整欄捲動。講評摘要的表格在約 320–340 px 寬的面板內**不必水平捲動**(第二十九輪 L4 量測:7 種視窗都是表格寬 = 面板寬 338 px,顯示捲軸時 318 px):
  指標名稱欄與時間 / 補充欄各至少 6em(名稱不逐字換行),長的英文識別字(例:`speed(manoeuvring.timeOverSpeedLimit_s)`)優先在 `.` `(` `_` 之後斷行(`<wbr>`),
  仍放不下才任意處斷行;數值欄與時間欄只在「 · 」「 → 」之後換行(例:舵角分布「0-5° 01:00 · 5-10° 00:00 · …」每段一行;數值與單位不拆開);
  「階段」列的數值欄改為段數、各階段放在時間欄。更正:L3 時本節寫「名稱在表格內換行」,實際上名稱欄被擠到約 25 px(一字一行),
  時間欄不換行,表格仍有約 1012 px 寬、要在巢狀捲動區裡水平捲動(L4 修正)。
  寬度 ≤ 1900 px 時 conning 條那一列與教官站相同給 220 px / 30vh(原本 22vh,1366×768 約 169 px,兩列方塊的下半被切掉)。
- ECDIS、雷達、講評報告頁:第二十九輪沒有量測、版面未改(講評摘要元件只用在重播檢視與簡化模式的結束頁)。

### 2.4 情境編輯器(教官站「情境編輯」分頁;`components/instructor/scenario-editor*.ts`)

欄數依編輯器本身的寬度以 container query 切換:≥ 1800 px 三欄、1150–1800 px 兩欄、更窄一欄(每欄至少約 560 px)。
面板內的格線依面板寬度一列一至三組「標籤 + 輸入」,放不下就換列;標籤不換行。細節見 `docs/design/scenario-engine.md` 第 6.1 節「版面」。

## 3. 改版面時的規則

1. 不縮小字級、不縮小觸控目標(按鈕 / 輸入框高度)來硬塞。
2. 不用 `overflow: hidden`、`text-overflow: ellipsis` 把控制項或標籤裁掉來「通過」;內容放不下時讓所在的面板或欄**自己捲動**(`overflow-y: auto`)。
3. 關鍵控制(第 4 節清單)必須不捲動就看得到並點得到。
4. 不隱藏功能(教官小面板、警報按鈕等);窄時改排法。
5. 改完跑第 5 節的量測與端對端測試,並在 1366×768 與 1536×864 各看一張截圖。

## 4. 判定(端對端測試與開發量測共用)

判定函式在 `tests/e2e/support/layout.ts`(`probeLayout` 以 `page.evaluate` 送進頁面執行,`layoutFailures` 列出不合格項;
`BRIDGE_LAYOUT` / `INSTRUCTOR_LAYOUT` 是關鍵控制與關鍵清單):

1. 每個可見的 button / input / select / textarea:中心點的最上層元素(穿過 shadow DOM)必須是自己或自己的後代(與 Playwright 點擊前的攔截檢查相同);
   不是的話逐一 `scrollIntoView` 後再判定 — 只允許靠使用者捲得動的容器(`overflow` 為 auto / scroll)捲到,靠 `overflow: hidden` 才捲得到者視為被裁切。
2. 關鍵控制不必捲動就整個看得到(中心點與四邊中點都點得到);關鍵清單(警報清單、事件串流)的可見高度足夠,前幾列完整落在可見範圍內。
3. 面板(`brm-*` 元件)內容不溢出自己的外框(或自己會捲動)、面板之間的可見外框不相交、不在視窗內的面板必須位於可捲動的容器內;
   浮貼的面板(`position: absolute`,例:航跡圖左上角的外力讀數)可見外框不超出它的定位容器(第二十九輪 L4 加入:
   讀數是 `pointer-events: none`,判定 1 的點擊檢查看不出它蓋住了 BNWAS)。
4. conning 條各方塊內的元素沒有水平裁切(`scrollWidth ≤ clientWidth + 1`)。
5. 整頁沒有捲軸。
6. 按鈕內的文字沒有被自己的 `overflow` 切掉、也沒有溢出鈕外(每個可見的 button:`scrollWidth ≤ clientWidth + 1`;第二十九輪 L4 加入:
   判定 1 只看中心點點得到,1093×614 的車鐘鈕數值被切掉、艏側推快速鈕的「100」溢出鈕外都沒有抓到)。
   對修正前的建置,這兩項在 1093×614 的駕駛台(E13)列出 7 個問題(浮貼讀數 1、車鐘 4、快速鈕 2),修正後為 0。
