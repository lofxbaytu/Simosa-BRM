# 修改指南 — 想改什麼、改哪裡、跑哪個測試

> 讀者:試行後接手修改的開發者或 AI 工作階段。目的:不必重新探索程式碼。路徑皆為儲存庫相對路徑;撰寫於第二十七輪(基底 f240014,2026-11-11)。
> 先判斷改動屬於哪一級,再查第 2 節主表:
>
> - **一級「內容與參數」**(不動程式):情境 YAML、公司程序參數集、行為錨定、啟動設定、船舶係數、區域幾何。用教官站的情境編輯器或直接改資料檔,以簽章更新包(`simosa-pkg pack`)送上船;不需重新建置。兩個例外:行為錨定是建置時打包進報告頁的 JSON(要 `pnpm build` 並走軟體更新包);啟動設定 `config/*.json` 不在任何更新包內(在該筆電上直接編輯)。
> - **二級「單一模組的程式修改」**:只動一個模組(一個面板、一種 NMEA 句子、一條評估規則),不改 `src/Contracts/` 的 schema、不改狀態雜湊;跑該模組的測試專案即可,以軟體更新包(`tools/build-release.sh`)發行。
> - **三級「跨模組或動到契約」**:動到 `src/Contracts/*.schema.json`、C#/Python 對等、狀態雜湊、黃金測試或紀錄夾具;必須照第 3 節同步清單逐檔處理,並跑全部套件。
>
> 原則:能用一級解決就不要寫程式;新功能以情境旗標啟用、預設關閉,既有情境的狀態雜湊與夾具不得改變(規劃書第 14 章、CLAUDE.md「確定性」);註解與文件用繁體中文並引用規劃書章節/需求 ID(R1–R14、D1–D20)。

## 2. 主表:想改什麼 → 改哪裡 → 跑哪個測試 → 級別

測試欄的縮寫:**SimCore** = `dotnet test tests/SimCore.Tests -c Release --filter <類別名>`(**Visual.Shared**、封裝等其他測試專案的類別,把路徑換成對應的 `tests/<專案>.Tests`;`--filter` 要給**類別名**,一個測試檔可能含多個類別,檔名不一定是類別名);**vitest** = `cd src/Instruments.Web && pnpm exec vitest run tests/<檔名>`;**pytest** = `cd src/Tools.Calibration && uv run pytest tests/<檔名>`。完整指令見第 5 節。

重產後 `git diff --stat tests/SimCore.Tests/Golden` 應只動到預期的檔;再跑對應的 C# 與 pytest 測試。Python 是黃金檔的來源,C# 是被比對的一方 — 兩邊公式要先改成一致,不能只重產讓測試變綠。

**核心紀錄夾具重錄**(`docs/design/scenario-library.md` 第 7、14.5 節的程序):

```bash
. /etc/profile.d/dotnet.sh
dotnet build src/SimCore.Host -c Release
dotnet run --project src/SimCore.Host -c Release --no-build -- --scenario data/scenarios/E02_coastal_traffic_strait.yaml --validate
dotnet run --project src/SimCore.Host -c Release --no-build -- --scenario data/scenarios/E02_coastal_traffic_strait.yaml \
    --duration 60 --timescale 10 --record build/tmp/fixtures/E02.jsonl --no-ws --no-udp --no-nmea --no-vhf --no-media
dotnet run --project src/SimCore.Host -c Release --no-build -- --replay build/tmp/fixtures/E02.jsonl   # 雜湊/事件/summary 須一致
```

再把紀錄**縮短**後放進夾具目錄:保留 header、全部 event、summary、footer。分兩類:(a) 一般情境(60 s,finalTick 3000):state 每 500 tick 留一筆(共 6 筆)、snapshot 留 tick 500 那一份;(b) 舊夾具 E01/E05/E07 用 `--duration 300`(finalTick 15000)、E08/E09 用 `--duration 600`(finalTick 30000),snapshot 留 tick 500/5000/15000 三份,state 間距 E05/E07 為 500 tick、E01/E08/E09 為 1000 tick — `core-record.test.ts` 與報告頁測試對這些舊夾具有逐項斷言(例如 E05:state 30 筆、finalTick 15000),重錄時長度與間距不可改。**縮短腳本沒有進版控**(歷來是各輪的一次性腳本);重錄時照此規則寫一個放 `build/tmp/`,並以現有夾具的行數核對(例如 `record-E02_coastal_traffic_strait-core.jsonl`:state 6、snapshot 1)。重錄後跑 vitest `core-record.test.ts` 與 pytest `test_scenario_params.py`;暫時無法重錄時把差異路徑列入 `test_scenario_params.py` 的 `KNOWN_FIXTURE_DRIFT`(目前為空,應保持為空)。

長情境的完整驗證另以 `--duration 900 --timescale 10` 錄製後 `--replay`(驗證後刪除紀錄,檔案可達數百 MB)。

## 5. 測試怎麼跑

以 `README.md`「測試」一節與 `docs/design/testing.md` 為準;以下是最常用的形式。所有輸出在 `build/`、快取在 `.cache/`。

```bash
# C#(容器:先載入 dotnet;Ubuntu 套件版 SDK 8.0.133 = C# 12,沒有 WindowsDesktop SDK,Shell.WebView2 只建空組件並警告屬正常)
. /etc/profile.d/dotnet.sh
dotnet build SimosaBRM.sln -c Release
dotnet test tests/SimCore.Tests -c Release --no-build                              # 最大的一包
dotnet test tests/SimCore.Tests -c Release --no-build --filter RollModelTests      # 只跑一個類別
dotnet test tests/Sensors.Radar.Tests -c Release --no-build                        # 其餘:Console.Serial.Tests、Shell.Core.Tests、Tools.Packaging.Tests、Visual.Shared.Tests

# 網頁
cd src/Instruments.Web && pnpm test && pnpm exec tsc --noEmit -p .
cd src/Instruments.Web && pnpm exec vitest run tests/roll-inclinometer.test.ts                # 只跑一檔

# Python
cd src/Tools.Calibration && uv run pytest -q
cd src/Tools.Calibration && uv run pytest tests/test_roll.py -q

# 啟動腳本與 PowerShell
bash tools/launch/tests/launch-tests.sh
bash tools/run-ps-tests.sh --install          # 第一次:把 pwsh 裝到 .cache/dotnet-tools;之後不必加 --install

# 端對端與 soak(都需獨佔 CPU,不要與其他套件併行)
bash tools/run-e2e.sh                         # 已建置:--skip-build;只跑部分:-- --grep 雷達
node --test tests/soak/report.test.mjs
bash tools/soak-test.sh --minutes 10 --clients 3 --skip-build
```

注意事項:

- **整套 `dotnet test SimosaBRM.sln` 要加 `-m:1`**(`.github/workflows/ci.yml` 的 Windows 工作同此):測試專案並行時,`tests/Console.Serial.Tests/HostEndToEndTests.cs` 的真實 Host 子程序(即時 50 Hz)會被 SimCore.Tests 擠到逾時。平常只跑改到的測試專案。
- **端對端的 Chromium**:`tools/run-e2e.sh` 未設 `E2E_CHROMIUM` 時用 Playwright 管理的 Chromium(`PLAYWRIGHT_BROWSERS_PATH`;本容器 `/opt/pw-browsers`,CI 裝到 `.cache/pw-browsers`);要用別的瀏覽器時以 `E2E_CHROMIUM=<執行檔>` 指定(錄影案例需要完整版 Chromium,不是 headless shell)。不要在船上或開發機隨意 `playwright install`(會連網際網路)。
- **PowerShell 測試**:沒有 pwsh 時 `tools/run-ps-tests.sh` 只做靜態檢查(`tools/pscheck.py`、`tools/installer/check-iss.py`)並回報略過;`--install` 以 `dotnet tool install` 安裝到專案內。`--only pscheck|iss|syntax|tests|whatif|soak` 可只跑一步。
- **C# 語法限制**:容器 SDK 為 C# 12,async 方法內不可宣告 `Span` 區域變數(Windows 開發機的新 SDK 不會報,CI 也不會,容器會)。
- **uv**:在專案根目錄或 `src/Tools.Calibration` 下執行,相對 `cache-dir` 才會解析到專案內。
- **視景無頭檢查** `tools/visual-headless-check.sh` 需要 Godot 執行檔(`--godot <路徑>` 或放在 `.cache/godot/`);容器重建後需重新取得。
- 各層級的定位、常見失敗與 flaky 處理:`docs/design/testing.md` 第 4.4 節。
