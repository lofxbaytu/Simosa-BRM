# 評估者指引(內部 BRM 課程行為標記評估)

> **內部訓練用途(D1):本指引規範公司內部 BRM 課程的評估,評估結果不連到任何法定證書,亦不作為任職處分的直接依據(規劃書第 8.4 節)。**
> 依據:規劃書第 2.1 節(STCW A-II/1 BRM 五項準則、A-II/1 與 A-II/2 領導與團隊合作八項準則)、第 2.2 節(A-I/12 評估程序)、第 8.2 節(行為標記、錨定與校準)、第 8.3 節(自動指標)、第 8.4 節(講評);實作:`src/Instruments.Web/src/lib/brm-markers.ts`(快速標記五類)、`src/Instruments.Web/src/report/behavioural-anchors.json`(錨定描述 v0.1.0-draft)、`marker-form.ts`(評估表與雙評一致率 `computeAgreement`)、`admin-records.ts`(校準紀錄、`CALIBRATION_TARGET` 0.8)。
> 版本:v0.1(2026-10-23,草案);核准人:待訓練負責人(訪船船長)核准;A-I/6 與 A-I/12 條文內容以現行官方文本核對(附錄 C)。假設事項集中於第 9 節。

### 3.3 評分尺度與錨定

| 分數 | 標籤 | 錨定用法 |
|---|---|---|
| 1 | 不可接受 | 符合該要素「1 分」錨定描述;必附時間戳與觀察描述 |
| 2 | 待改進 | 介於 1 與 3 分錨定之間;必附時間戳與觀察描述(`lowScoreThreshold` 2) |
| 3 | 可接受 | 符合「3 分」錨定:主要行為有做到,但有遺漏且經提醒補正 |
| 4 | 良好 | 介於 3 與 5 分錨定之間;建議附一則正向觀察 |
| 5 | 優異 | 符合「5 分」錨定:全程、主動、含狀況改變時的調整 |

錨定描述範例(全文見 `behavioural-anchors.json`,評估表與講評站同時顯示):

| 要素 | 1 分 | 3 分 | 5 分 |
|---|---|---|---|
| 閉環溝通/複誦 | 舵令/車令多次未複誦且無人糾正 | 多數複誦但偶有遺漏,經他人提醒補正 | 全程複誦並回報執行 |
| 果斷與權威的運用 | 關鍵時刻猶豫或放任引水人/資深者的明顯錯誤;或以權威壓制意見 | 能下達決定但時機偏晚或語氣含糊;對質疑有回應但未說明理由 | 適時清楚地下達決定並說明理由;歡迎質疑,必要時接管(含對引水人) |
| 工作負荷管理與授權 | 獨攬多項任務而過載,遺漏關鍵事件;干擾未被隔離 | 大致有授權,高負荷時段仍有重疊或遺漏,事後補正 | 預見高負荷時段並事先分派、隔離干擾;持續監看分派後的執行 |

錨定使用規則:(1) 以**可觀察行為**評分,不以推測的態度或意圖評分;(2) 同一要素在練習中多次出現時,以整體表現評,但 1–2 分的觸發事件須逐一記錄時間戳;(3) 要素未被情境激發(例如 E01 無衝突可解)時標記「未觀察」而非給 3 分;(4) 錨定為草案(`status: draft`),評估員發現錨定不足或歧義時記入校準會議紀錄,改版後全體再校準(第 5.4 節)。

### 3.4 缺失分類(SIRE 2.0 方式)

每則 1–2 分觀察另標記缺失類型:硬體 / 程序 / 人員;人員再分 熟悉度、任務設計、設備、緊張/語言、疲勞(`deficiencyTypes`、`humanFactors`)。目的是區分訓練可改善的項目與應回饋公司程序或設備的項目。

## 4. 評分流程

### 4.1 簡報(練習前 15–20 分鐘)

| 步驟 | 評估員動作 | 工具 |
|---|---|---|
| 1 | 確認參與者、角色與休息時間確認已完成 | 教官站 sessionInfo 面板 |
| 2 | 向學員說明受評要素、情境公開的評估規則(硬性失敗、容許帶、必要事件)與判定準則(課程大綱第 5、9 節) | 情境 `briefing`、`assessment` 區段 |
| 3 | 不透露升級觸發與「引水人是錯的」劇情 | — |
| 4 | 預先決定本練習的觀察重點要素(通常 6–9 項)與各要素的觀察時機(例如交接班→簡報要素;故障注入→決策與溝通) | 紙本觀察表 |
| 5 | 評估表建立(學員、情境、錨定版本)| 講評站 `report.html` 評估表 |

### 4.2 觀察(執行中)

| 原則 | 做法 |
|---|---|
| 即時標記 | 以快速鍵 1–5 記錄類別、plus/delta 與一句備註(`BrmMarkerStore`);每則標記自動帶模擬時間與步數,可於講評跳至該時刻 |
| 先記事實再評分 | 執行中只記「誰、何時、做了什麼/沒做什麼」;分數於講評前依錨定決定 |
| 對應時間戳 | 1–2 分必有標記;建議每項 4–5 分也有至少一則正向標記,避免只記負面 |
| 不介入 | 除安全凍結(擱淺/碰撞自動凍結)或情境腳本要求外,評估員不提示;船上簡化教官模式下帶領者兼評估員時,提示須記為標記並於評分時考量 |
| 自動指標 | 執行中不看自動評分;講評前再讀講評報告的指標與必要事件,作為對照(第 7 節) |

### 4.3 講評(執行後 30–40 分鐘)

依第 8.4 節五階段:(1) 反應階段 → (2) 團隊自我回顧(含標記重播)→ (3) 倡議-探詢分析 → (4) 推廣到 SOP 與公司程序 → (5) 總結與個人行動點。船上至少完成 (1)(2),其餘由訪船船長於訪船時或依紀錄補充。

| 階段 | 同儕評估作法(A-I/12 訓練程序第 6.6 段) | 評估員注意事項 |
|---|---|---|
| (1) 反應 | 每位學員一句「我當時最擔心的是…」 | 不評論、不糾正 |
| (2) 自我回顧 | 團隊先依五大類自評 1–5 分,互評一項做得好與一項可改進(Plus/Delta);評估員再播放標記片段 | 自評分數記入講評紀錄,不取代評估員分數;差距 ≥2 分者於 (3) 討論 |
| (3) 倡議-探詢 | 「我在 14:32 看到 X,我擔心的是…,你們當時的想法是?」 | 以標記時間戳為錨;聽完學員說明後再定分 |
| (4) 推廣 | 對照公司程序參數(講評報告顯示參數集版次與來源文件) | 程序本身的問題記為「程序」缺失並回饋訓練負責人 |
| (5) 總結 | 每人 1–2 個行動點;指定下個練習的觀察重點 | 不公布 E20 判定前先完成雙評協調 |

### 4.4 紀錄(講評後當日)

| 項目 | 做法 |
|---|---|
| 評估表完成 | 15 要素評分或「未觀察」;1–2 分附時間戳與觀察描述(`validateMarkerForm` 會擋下缺漏);附快速標記(`attachMarker`) |
| 判定 | E20:通過/未通過與理由(第 7 節);E01:基線,不判定 |
| 匯出 | 評估表 JSON(`exportForms`)、講評報告列印/PDF、班次紀錄 CSV;隨紀錄包回傳 |
| 學員簽認 | 學員於個人訓練紀錄簽認已聽取講評(紙本;系統無簽名欄,ASSUMED) |
| 爭議 | 學員不同意時記入備註;複查流程待 D20 |

## 5. 評估者校準

| 步驟 | 內容 | 工具/紀錄 | 狀態 |
|---|---|---|---|
| 5.1 基準錄影 | 3 段基準錄影(E20 或等效情境),於第 2 階段驗證練習或第 3 階段試行前預演錄製;涵蓋高、中、低三種表現水準(ASSUMED) | 核心紀錄 + 教官站紀錄;語音/影像擷取未實作,暫以核心重播 `?mode=replay` 加現場錄影設備(ASSUMED) | 需實機 |
| 5.2 標準評分 | 外部評估員與航海專家共同訂定每段的 15 要素標準分與理由;受校準者不參與 | 標準評分表(JSON)存於教官筆電校準資料夾 | 需實資料 |
| 5.3 上線校準 | 每位評估員對 3 段錄影獨立評分;與標準評分比較,**≥80% 的要素在 ±1 分內**方可獨立評分(`computeAgreement`:`tolerance` 1、`target` 0.8);未達者討論差異後補做 | 一致率填入教官資格紀錄 `calibrations[]`(日期、基準錄影、一致率)並隨 CSV/JSON 匯出 | 一致率計算與紀錄已實作;一致率目前人工輸入 |
| 5.4 再校準 | 每年一次以新基準錄影再校準(`recalibrationDue` 逾 365 天提醒);評估表或錨定描述改版時重做 | 同上 | 已實作提醒 |
| 5.5 雙評 | 每期至少 E20 由訪船船長與該船船長獨立評分(船長本人受訓時由另一船船長或外聘評估員依錄影評分);目標 ≥80% 要素 ±1 分;差異於下次訪船前協調,記錄原因與最終分數,於補充講評說明 | 講評站雙評表 → `computeAgreement`;協調紀錄 | 已實作一致率;協調紀錄以備註欄 |
| 5.6 監督經驗 | 訪船船長最初 2 次有評估的練習由外部評估員監督並簽署;船長最初 2 次雙評由訪船船長監督並簽署 | 監督紀錄存入教官資格紀錄(`note` 欄,ASSUMED) | 需實資料 |

校準會議產出:(1) 各評估員一致率;(2) 差異最大的要素與原因(錨定歧義/觀察遺漏/標準不同);(3) 錨定修訂建議(送訓練負責人,版本化後改為 1.0.0)。

## 6. 常見偏誤與處理

| 偏誤 | 徵象 | 處理 |
|---|---|---|
| 結果偏誤(outcome bias) | 任務安全完成就全部給高分,或一次硬性失敗就全部給低分 | 先逐要素依錨定評,再看結果;硬性失敗只決定「通過/未通過」,不自動拉低各要素分數 |
| 月暈效應 | 一位學員(常是船長)的整體印象影響各要素 | 以快速標記的時間戳逐件評;每要素至少引用一則觀察 |
| 趨中 | 全部 3 分、未觀察也給 3 分 | 未被激發的要素標「未觀察」;校準時檢視分數分布 |
| 寬大/嚴苛 | 評估員平均分明顯高/低於標準評分 | 校準一致率低於 80% 即補做;雙評差異記錄原因 |
| 近因效應 | 只記得最後 15 分鐘(故障處置) | 預先決定各階段觀察重點(4.1 第 4 步);交接班與簡報階段必有標記 |
| 熟識/階級偏誤 | 第二評估員(船長)評自己的船副;船副評估船長時不敢給低分 | 雙評獨立完成後才交換;船長本人受訓時改由另一船船長或外聘評估 |
| 自動指標替代 | 直接把自動評分當行為分數 | 自動指標只作對照(第 7 節);指標異常但行為正確(例如為避讓而偏航)須以行為評 |
| 文化/語言偏誤 | 以語言流利度評溝通要素 | 溝通要素評的是閉環、簡報結構、意圖分享,非語言能力;語言問題記為「緊張/語言」缺失類型 |
| 模擬器偏誤 | 因模型與實船差異(無浪、港口示意幾何、FSB2 海報值)造成的操作差異被評為缺失 | 不計分;記入練習設計/測試紀錄回饋開發 |
| 帶領者兼評估員 | 船上簡化教官模式下帶領者曾提示學員 | 提示記為標記;受提示後的行為不計入該要素的正向證據 |

## 7. 與自動指標(assessment)併用原則

| 原則 | 說明 |
|---|---|
| 首要準則 | 學員能**安全有效地完成任務**(A-I/12 評估程序第 7.6 段);硬性失敗(擱淺、碰撞、CPA/UKC 低於門檻;`AssessmentEngine` 一票否決)→ E20 判未通過,評估員仍完成 15 要素評分供講評 |
| 自動評分地位 | 自動評分(容許帶扣分、必要事件逾時/missed、`assessment.passMark` 70)在試行課程驗證前**僅作輔助**(第 8.3 節;講評報告標示錨定版本與「草案」);評估員最終判定優先,與自動評分不一致時記錄理由 |
| 對照用法 | 必要事件時間戳(故障辨識→行動→通知機控室、引水人登船前下風舷確認、交接班矛盾查證)對應溝通與決策要素;閉環遵循率對應 communication.closedLoop;干擾期間未處理事件對應 leadership.workload;XTD/UKC/速限對應 situationalAwareness.ownship |
| 參數依據 | 容許帶與門檻引用公司程序參數集(版次與來源文件顯示於講評報告);參數為 `ASSUMED-*` 來源者,評估員對其扣分保留判斷並記入備註 |
| 驗證 | 試行課程(第 14 章課程列)期間蒐集「自動評分 vs 評估員判定」對照,作為評分方法驗證紀錄;驗證前不以自動評分單獨判定通過 |
| 通過判定(ASSUMED) | 通過:無硬性失敗、自動評分 ≥ passMark、15 要素無 1 分、2 分以下 ≤3 項且均附觀察;其餘未通過。未通過者本版僅記錄與講評(D20) |
