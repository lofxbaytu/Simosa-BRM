# 本機資料位置 — 資料放 D: 或 G:,不放 C:

> 適用:Windows 開發機、船上筆電、教官筆電。訂於第二十八輪(2026-11-12,使用者指示);守則本文在 `CLAUDE.md`。

## 1. 守則

1. **所有要儲存在本機的資料都放在專案(安裝)資料夾內**,而這個資料夾放在 **D: 或 G:**(例如 `D:\Simosa BRM`、`G:\Simosa BRM`;可以是隨身碟)。程式與腳本不寫死磁碟代號,資料夾放在哪個磁碟就用哪個磁碟。
2. **C: 只放應用程式本身**(第 3 節)。
3. 某個項目放在隨身碟會**嚴重拖慢進度**時,**先取得訓練負責人同意**,才可以用第 4 節的例外開關把它放在 C:。沒有同意就維持預設。

環境變數由 `tools\setup-windows.ps1` 寫入(使用者層級,之後開的終端機都生效)。**TEMP/TMP 例外**:只改目前這個 PowerShell 工作階段,不寫使用者層級(否則會影響這個帳號的所有程式,隨身碟拔除時其他程式會失敗)。所以每次開新終端機做建置或測試前,先執行一次:

```powershell
.\tools\setup-windows.ps1 -SessionOnly
```

`tools\` 下的建置與啟動腳本(`build-release.ps1`、`simosa-pkg.ps1`、`soak-test.ps1`、`start-ship-laptop.ps1`、`start-instructor-laptop.ps1`、`visual-headless-check.ps1`)會自行設定,不必先執行上面這行。

## 3. 可以在 C: 的東西(應用程式與 Windows 自身)

- 應用程式的程式檔:.NET 8 SDK / 執行階段、Node.js、Git、uv、Microsoft Edge、WebView2 Runtime、Inno Setup(也可以裝在專案磁碟的 `\Tools\`,見 `setup-windows.ps1` 結尾的建議)。
- Windows 自身的設定:登錄(安裝程式只寫解除安裝資訊)、防火牆規則、網路介面設定。
- NuGet 的使用者設定檔 `%APPDATA%\NuGet\NuGet.Config`(NuGet 第一次執行時自動建立,數 KB,無法改位置)。
- 安裝程式(`SimosaBRM-Setup-*.exe`)執行期間的暫存(Windows `%TEMP%`,結束即刪)。

## 4. 例外開關(每一個都要先取得同意)

| 想放 C: 的項目 | 開關 | 效果 |
|---|---|---|
| 暫存檔(建置、測試時的大量小檔;放隨身碟最容易拖慢) | `setup-windows.ps1 -SystemTemp`;腳本層級:環境變數 `SIMOSA_SYSTEM_TEMP=1` | TEMP/TMP 留在 Windows 預設的 `C:\Users\…\AppData\Local\Temp` |
| 整個專案資料夾 | `setup-windows.ps1 -AllowSystemDrive` | 預設拒絕在系統磁碟執行;加了才繼續 |
| 安裝位置(安裝程式) | 確認對話框選「是」;靜默安裝加 `/ALLOWSYSTEMDRIVE=1` | 預設位置依序為 `D:\Simosa BRM`、`G:\Simosa BRM`;兩者皆無或自行改選系統磁碟時要求確認(預設「否」) |
| 瀏覽器端資料 | `start-ship-laptop.ps1 -DefaultBrowser`、`start-instructor-laptop.ps1 -DefaultBrowser` | 用 Windows 預設瀏覽器開頁面,資料存在該瀏覽器位於 `C:\Users` 的設定檔 |
| simosa-pkg 的安裝根目錄 | `--root <路徑>` 或環境變數 `SIMOSA_INSTALL_ROOT` | 未指定時依序為:程式所在的安裝根目錄 → 專案根目錄 → `D:\Simosa BRM` → `G:\Simosa BRM`;不會自動落到 C: |

## 5. 注意事項

- **不要手動在其他瀏覽器輸入網址開教官站或講評報告站**:草稿、參與者資料與訓練紀錄會存進那個瀏覽器在 `C:\Users` 的設定檔,而且和啟動腳本開的視窗互不相通。請用啟動腳本(專屬 Edge 設定檔)或 `-Shell`(WebView2 外殼)。
- 從網頁**下載**的檔案(情境 YAML、紀錄 JSON、講評報告與訓練紀錄匯出)存到 `build\downloads\`:WebView2 外殼由程式設定;專屬 Edge 設定檔在第一次建立時預先寫入下載位置(之後可在該 Edge 視窗的 設定 → 下載 調整,請維持在專案磁碟)。用 `-DefaultBrowser` 或手動開其他瀏覽器時,下載會到 `C:\Users\…\Downloads`。
- 隨身碟拔除前先用 `stop-all.ps1` 結束所有程序。
- 換磁碟代號(例如 D: 變 G:):重新執行一次 `.\tools\setup-windows.ps1`,使用者層級的環境變數會改指到新位置。

## 6. 在實機上確認

```powershell
.\tools\check-local-data.ps1                       # 檢查過去 24 小時
.\tools\check-local-data.ps1 -Since '2026-11-12 09:00'   # 檢查這個時間之後
```

只讀取、不修改。它列出:根目錄是否在系統磁碟、目前工作階段的環境變數是否都指到專案內、各工具「預設」會寫到 `C:\Users` 的位置是否有新資料(大小與最近寫入時間)。結束碼 0 = 沒有發現問題、1 = 有項目要處理、2 = 專案位於系統磁碟。

自動檢查(容器與 CI):`src/Tools.Calibration/tests/test_repo_datapaths.py`(設定檔與 `setup-windows.ps1`)、`tools/launch/tests/launch-common.tests.ps1`(`Set-LaunchProjectEnv`、瀏覽器設定檔位置)、`tests/Tools.Packaging.Tests/InstallLayoutDefaultRootTests.cs`(預設安裝根目錄不落到 C:)、`tools/installer/check-iss.py`(安裝程式預設位置與系統磁碟確認)、`tools/pscheck.py`(`.ps1` 的 UTF-8 BOM)。
