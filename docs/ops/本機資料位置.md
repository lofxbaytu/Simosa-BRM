# 本機資料位置 — 資料放 D: 或 G:,不放 C:

> 適用:Windows 開發機、船上筆電、教官筆電。訂於第二十八輪(2026-11-12,使用者指示);守則本文在 `CLAUDE.md`。

## 1. 守則

1. **所有要儲存在本機的資料都放在專案(安裝)資料夾內**,而這個資料夾放在 **D: 或 G:**(例如 `D:\Simosa BRM`、`G:\Simosa BRM`;可以是隨身碟)。程式與腳本不寫死磁碟代號,資料夾放在哪個磁碟就用哪個磁碟。
2. **C: 只放應用程式本身**(第 3 節)。
3. 某個項目放在隨身碟會**嚴重拖慢進度**時,**先取得訓練負責人同意**,才可以用第 4 節的例外開關把它放在 C:。沒有同意就維持預設。

**隨身碟的格式**:開發用(要執行 `pnpm install` 建置網頁)的磁碟必須是 **NTFS**。隨身碟出廠多為 exFAT 或 FAT32,不支援目錄連結,`pnpm install` 會以 `EISDIR` 失敗;FAT32 另有單檔 4 GB 上限(錄影、安裝檔)。FAT32 可用 `convert G: /FS:NTFS` 就地轉換(不清資料);exFAT 只能備份後重新格式化(會清空整顆磁碟,請先確認)。只執行發行版的船上 / 教官筆電不受這個限制。`setup-windows.ps1` 與 `check-local-data.ps1` 會檢查並提醒。

**安裝版的完整性核對**:`simosa-pkg release verify --dir <安裝根目錄> --installed`(`docs/ops/安裝與啟動.md` 第 2.4 節)把上表中安裝版會出現的位置 — `build\`、`.cache\`、`state\`、`store\`、`config\device\`、`config\trusted-keys\`、`config\packaging.json`、`data\records\`,以及岸上放入離線安裝檔的 `tools\webview2\`、`tools\dotnet\` — 視為執行期資料,其下清單沒有列的檔案不算「多出」;這份清單集中在 `src/Tools.Packaging/Common/InstalledPaths.cs`(測試與 `InstallLayout`、安裝程式 `[Dirs]` 對照)。新增本機資料位置時,這張表、`InstalledPaths` 與安裝程式三處一起改。

**環境變數怎麼生效**(開發機):

- `.\tools\setup-windows.ps1`:寫入使用者層級(之後開的終端機與 IDE 都生效)。**TEMP/TMP 例外**:只改目前這個 PowerShell 工作階段,不寫使用者層級(否則會影響這個帳號的所有程式,隨身碟拔除時其他程式會失敗)。
- `.\tools\setup-windows.ps1 -SessionOnly`,或雙擊 **`tools\dev-shell.cmd`**(開啟一個已設定好的 PowerShell 視窗):只設定那個視窗,不寫使用者層級。**專案在隨身碟時建議用這個方式** — 使用者層級的變數會讓這個 Windows 帳號的其他專案也把快取寫到隨身碟,拔除後它們會失敗;已寫入的可用 `.\tools\setup-windows.ps1 -Unregister` 移除。
- 直接在新開的終端機或 IDE 執行 `dotnet` / `pnpm` / `uv` 時,暫存檔仍會在 Windows 預設的 `C:\Users\…\AppData\Local\Temp`(TEMP 沒有寫成使用者層級):建置或測試請在 `dev-shell.cmd` 開的視窗內做,IDE 也從那個視窗啟動。
- `tools\` 下的建置與啟動腳本(`build-release.ps1`、`simosa-pkg.ps1`、`soak-test.ps1`、`start-ship-laptop.ps1`、`start-instructor-laptop.ps1`、`visual-run.ps1`、`visual-headless-check.ps1`)會自行設定 .NET / NuGet 的快取與 TEMP/TMP,不必先執行 setup;這幾個變數(以及 `NODE_COMPILE_CACHE`、`npm_config_cache`、`PWTEST_CACHE_DIR`)已設定但指到專案外時(例如專案從 D: 複製到 G: 後殘留的舊路徑),在該次執行改指回專案內。其餘變數(`PNPM_HOME`、`UV_*`、`PLAYWRIGHT_BROWSERS_PATH`)腳本不處理:換磁碟後請重新執行 `setup-windows.ps1` 或改用 `dev-shell.cmd`。

## 3. 可以在 C: 的東西(應用程式與 Windows 自身)

- 應用程式的程式檔:.NET 8 SDK / 執行階段、Node.js、**corepack 下載的 pnpm 本體**(`%LOCALAPPDATA%\node\corepack`)、Git、uv、Microsoft Edge、WebView2 Runtime、Inno Setup、Arduino IDE 與其板套件 / 工具鏈、OpenCPN(多數也可以裝在專案磁碟的 `\Tools\`,見 `setup-windows.ps1` 結尾的建議)。
- 安裝程式建立的開始功能表與桌面捷徑(`.lnk`;系統管理員安裝時在 `C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Simosa BRM\` 與公用桌面,屬應用程式的一部分)。
- Windows 自身的設定與紀錄:登錄(安裝程式只寫解除安裝資訊)、防火牆規則、網路介面設定、事件記錄與當機報告。
- 各應用程式自己的使用者設定檔(數 KB,無法或不適合改位置):NuGet 的 `%APPDATA%\NuGet\NuGet.Config`、Git 的 `%USERPROFILE%\.gitconfig`(`git lfs install`、`safe.directory` 都寫在這裡)與認證管理員、PowerShell 的指令歷史與模組快取、IDE 自己的設定與快取。
- 顯示卡驅動程式自己的著色器快取(NVIDIA / Intel / AMD;位置由驅動程式決定)。
- 安裝程式(`SimosaBRM-Setup-*.exe`)執行期間的暫存(Windows `%TEMP%`,結束即刪)。

## 5. 注意事項

- **視景請由啟動腳本啟動**(`start-ship-laptop.ps1`、`tools\visual-run.ps1`):直接雙擊 `app\visual\SimosaBRM.Visual.exe` 時,Godot 會把引擎 log 與著色器快取寫到 `C:\Users\…\AppData\Roaming\SimosaBRM-Visual`(Godot 匯出檔的使用者資料位置只能在啟動時用環境變數改)。
- **不要手動在其他瀏覽器輸入網址開教官站或講評報告站**:草稿、參與者資料與訓練紀錄會存進那個瀏覽器在 `C:\Users` 的設定檔,而且和啟動腳本開的視窗互不相通(外殼各頁、專屬 Edge 設定檔、其他瀏覽器是三處各自獨立的資料)。請用啟動腳本(專屬 Edge 設定檔)或 `-Shell`(WebView2 外殼);教官筆電執行 `start-instructor-laptop.ps1`。
- **先前用其他瀏覽器存過資料時的搬移**(一次性):以 `-DefaultBrowser` 啟動一次 → 在講評報告站把名冊、班次、評估表、教官與證書紀錄匯出成 JSON,情境編輯器的草稿用「下載 YAML」存檔 → 正常啟動(專屬 Edge 設定檔)後在講評報告站匯入 JSON、在情境編輯器開啟 YAML → 在舊瀏覽器清除 `127.0.0.1` 的網站資料。換開啟方式(外殼 ↔ Edge)時也一樣先匯出再匯入。
- 從網頁**下載**的檔案(情境 YAML、紀錄 JSON、講評報告與訓練紀錄匯出)存到 `build\downloads\`:WebView2 外殼每次啟動時設定;專屬 Edge 設定檔在第一次建立時預先寫入下載位置,之後每次啟動檢查 — 不在目前根目錄內(例如專案換了磁碟代號)就改回 `build\downloads`(該 Edge 視窗還開著時只警告)。講評報告用「列印 → 另存為 PDF」時,存檔對話框請選 `build\downloads`(WebView2 外殼的對話框預設資料夾可能是 `C:\Users` 下的文件或下載,尚未在實機確認)。
- **拔除隨身碟前**:執行 `stop-all.ps1`(會結束所有程序,並請以專屬設定檔開啟的 Edge 視窗關閉;`-KeepBrowser` 可保留),確認 Edge 視窗都已關閉。Edge 還開著就拔除會損毀設定檔內的草稿與訓練紀錄。開發機另可執行 `dotnet build-server shutdown`。
- 換磁碟代號或把專案複製到另一個磁碟(例如 D: → G:):開發機重新執行一次 `.\tools\setup-windows.ps1`(使用者層級的環境變數改指到新位置),或改用 `dev-shell.cmd`;啟動腳本與 Edge 的下載位置會自行修正。
- 解除安裝(安裝程式)只刪 `build\logs`、`build\tmp`;練習紀錄、設定、瀏覽器端資料(`build\webview2`、`build\browser`)與 `build\downloads` 都保留。
- pnpm 請用固定版 **10.28.0**(`corepack enable pnpm; corepack install -g pnpm@10.28.0`):11 以上不讀 `.npmrc` 的 `store-dir` / `cache-dir` / `state-dir`,快取與狀態會落到 `C:\Users\…\AppData\Local\pnpm-cache`、`pnpm-state`,而且 `pnpm install` 會失敗;`setup-windows.ps1` 偵測到時會警告。
- **手動執行各程式時的寫入位置**(啟動腳本的用法都在根目錄內,不受影響):
  - **相對路徑一律以根目錄為準,不以目前目錄為準**:SimCore.Host 的 `--record <路徑>`(專案根目錄);`SimosaBRM.Console.Serial` 的 `--log`(預設 `build\logs\console.log`)與 `--loopback <讀>,<寫>`(專案根目錄;安裝版單獨執行、沒有設 `SIMOSA_BRM_ROOT` 時為安裝根目錄 — 程式所在位置往上同時含 `data\` 與 `app\` 的資料夾;兩者都找不到才以目前目錄為準);WebView2 外殼的 `--profile`(安裝根目錄;找不到含 `data\` 的上層時以目前目錄為準);simosa-pkg 寫入用的 `--out`(keygen、pack、store report)、`--store`、`--to`(store backup、export)、`--from`(import)、`verification add` 的 `--file`、`release manifest` 的 `--dir`(`--root`,未指定時為預設安裝根目錄;該資料夾不存在時以目前目錄為準)。simosa-pkg 讀取**本工具產生的檔案**時 — `--key`、`trust add --file`、`verification list --file`、`pack --verification`、`--push`、`store register-device --public`、`release verify --dir`、`inspect` / `verify` / `apply` / `records accept-report` / `store import` 的檔案 — 相對路徑先找目前目錄(原本的行為),沒有時再找上述的根目錄,所以在根目錄以外的目錄以相對路徑操作時,`keygen --out` → `pack --key`、`verification add` → `pack --verification`、`pack --out` → `sync --push` 仍彼此找得到;兩處都有同名檔時用目前目錄的並提醒一行(要用根目錄的請給絕對路徑)。其他輸入(`--scenario`、`--parameters`、`--baseline`、`--data-root`、`--record`、`pack` 的 `--file` / `--dir` 來源)與 `--root` 本身仍以目前目錄為準。`config\packaging.json` 的 `store`、`recordsDir` 相對路徑以安裝根目錄為準(原本就是)。
  - **寫入位置在根目錄之外、而且位於系統磁碟(`%SystemDrive%`,通常 C:)時拒絕**,以非零結束碼結束並說明守則與第 4 節的開關;包括 `config\packaging.json` 的 `store`(用到紀錄庫的指令)與 `recordsDir`(會依已備份回報刪除舊紀錄的 `records accept-report`、`import --role ship`、`serve`)的絕對路徑。根目錄:SimCore.Host 為專案根目錄,操控台服務與外殼為上述的根目錄,simosa-pkg 為安裝根目錄與專案根目錄(`SIMOSA_BRM_ROOT` 或含 `Directory.Build.props` 的上層;`build-release` 把開發金鑰寫到發行目錄外的 `build\release\dev-keys` 因此照常)。隨身碟(E: 等)與網路路徑(`\\server\share`)照常:教官筆電的 `export --to E:\`、`store backup --to E:\` 不受影響。`\\?\C:\…`、正斜線、`..`、大小寫都先正規化再判斷;段落結尾的空白與句點照 Windows 的規則(中間段只去掉一個結尾句點、空白保留,所以 `C:\Simosa BRM \records` 是根目錄旁的另一個資料夾,算根目錄外;只有最後一段去掉全部結尾的空白與句點)。經同意確實要寫到系統磁碟時設 `SIMOSA_ALLOW_SYSTEM_DRIVE=1`。非 Windows 不檢查。
  - 原本就限制在專案資料夾內(根目錄外一律拒絕,不分磁碟)的:SimCore.Host 的 `--nmea-file`、`--media-dir`、`--stop-file`。雷達服務(`Sensors.Radar.Host`)與網頁伺服(`simosa-web`)沒有寫檔的選項。
  - 判斷邏輯只有一份:`src/SimCore/Ship/LocalDataGuard.cs`(各程式以專案參照共用);測試見第 6 節。
- Arduino IDE(操控台韌體)的下載暫存與編譯輸出預設在 `C:\Users`,導回方式見 `firmware\teensy-console\README.md`(尚未在實機驗證)。
